## 브랜치 3종

| 브랜치 | 역할 | 여기서 직접 작업하나요? |
|---|---|---|
| `feature/*` | **실제 작업 공간**. 기능 하나당 하나씩 | ✅ 여기서 작업 |
| `dev` | 만든 기능을 모아서 잘 도는지 확인 | ❌ 병합으로만 |
| `prod` | 배포해도 되는지 최종 확인 | ❌ 병합으로만 |
| `main` | **여기서 실제 배포가 나감**. 가지를 치는 기준이기도 함 | ❌ 절대 직접 작업 금지 |

## 흐름

```
main ──(가지 치기)──→ feature/cat-note-db ──→ dev ──→ prod ──→ main ──→ 🚀 배포
  ↑                        (작업)          (확인)  (최종확인)   ↑
  └────────────────────────────────────────────────────────────┘
                   main이 시작점이자 도착점
```

**왜 `main`이 마지막이냐면** — 실제 배포가 `main`에서 나가거든요.
`main`의 프론트 코드가 `world-holicat-frontend`로 복사되고, Vercel이 그걸 배포해요.
그래서 **`main`에 들어간 것 = 사용자가 보는 것**이에요.

## 작업 순서 (매번 이대로)

### 1. 새 작업 시작 — main에서 가지 치기

```bash
git checkout main
git pull
git checkout -b feature/cat-note-db
```

> 💡 **항상 `main`에서 시작**해요. `git pull`을 꼭 먼저 해서 최신 상태에서 가지를 쳐야 나중에 충돌이 안 나요.

### 2. 작업하고 커밋

```bash
git add .
git commit -m "feat: 고양이 수첩 테이블 8개 추가"
```

### 3. 올리기

```bash
git push -u origin feature/cat-note-db
```

### 4. dev에 합쳐서 확인

```bash
git checkout dev
git merge feature/cat-note-db
git push
```

> 회사처럼 하려면 이 단계를 **PR(Pull Request)**로 해요. 깃허브에서 `feature/... → dev`로 PR을 만들고, 스스로 코드를 한 번 훑어본 뒤 머지하면 돼요. 혼자 해도 "내가 뭘 바꿨는지" 다시 보게 돼서 실수를 잘 잡아요.

### 5. 작업 끝난 가지 지우기

```bash
git branch -d feature/cat-note-db
git push origin --delete feature/cat-note-db
```

### 6. 배포까지 흘려보내기

```bash
# dev에서 확인 끝났으면 prod로
git checkout prod && git merge dev && git push

# prod에서 최종 확인 끝났으면 main으로 → 이게 배포되는 것
git checkout main && git merge prod && git push
```

그다음 프론트 코드를 배포 저장소로 옮겨야 실제 사이트에 반영돼요 (아래 ⚠️ 참고).

## 백엔드 저장소(`world-holicat-backend`)도 브랜치를 나눠요

> ⚠️ **여기가 더 위험해요** — 백엔드는 `main`에 푸시하는 순간 **운영 서버에 자동 배포**돼요.
> 모노레포와 달리 "합치기만 하고 배포는 나중에"가 안 돼요.

| 브랜치 | 역할 |
|---|---|
| `feature/*` · `fix/*` · `test/*` | 작업 공간. **여기선 배포 안 돌아요** |
| `main` | **푸시 = 즉시 운영 배포** 🚀 |

### 작업 순서

```bash
cd ../world-holicat-backend
git checkout main && git pull
git checkout -b feature/note-id-check     # 작업 브랜치에서 시작

# ... 작업하고 커밋 ...
.venv/bin/pytest                          # 테스트 통과 확인!
git push -u origin feature/note-id-check  # 여기까지는 배포 안 됨

# 다 됐으면 main으로 → 이때 배포돼요
git checkout main && git merge feature/note-id-check && git push
```

**핵심: 테스트가 통과한 뒤에만 `main`으로 합쳐요.** `main`에 들어간 순간 사용자가 쓰는 서버가 바뀌거든요.

> 배포를 미루고 싶으면 커밋 메시지에 `[skip ci]`를 넣으면 워크플로가 건너뛰어요.
